# KeyCard App Breakdown & Architecture

This document serves as a comprehensive audit and breakdown of all features, functionality flows, architectural conditions, and capabilities of the **KeyCard** application. 

KeyCard is a SwiftData and SwiftUI powered iOS application designed to store, manage, and emulate MIFARE Classic 1K NFC cards using a custom ESP32 + PN532 hardware bridge via Bluetooth Low Energy (BLE), as well as integrating with native Apple frameworks like CoreNFC and ActivityKit.

---

## 1. Core Capabilities & Feature Set

### Card Management (Local Library)
- **Persistent Storage**: Utilizes SwiftData to persistently store `Card` entities on the device.
- **Visual Representation**: Cards are rendered using an Apple Wallet-style overlapping `VStack` layout.
- **Drag-and-Drop Reordering**: Users can long-press and drag cards in the `CardLibraryView` to reorder them. The order is saved via the `orderIndex` property on the `Card` model.
- **Search & Filtering**: A native SwiftUI `.searchable` modifier allows filtering cards by name or UID in real-time.

### Card Import
- **Raw Dump Parsing**: Native processing of `.bin` or `.json` card dumps generated by tools like Proxmark3 (`hf mf dump -k ...`).
- **File & Clipboard Support**: Users can import dumps via the iOS File picker (`.fileImporter`) or directly paste hex/JSON payloads from the clipboard.
- **Data Extraction**: Extracts critical parameters automatically: UID, ATQA, SAK, Sector Keys, and Block Data.

### Emulation & Hardware Bridging
- **BLE Command System**: The app communicates with an ESP32 hardware bridge using Bluetooth Low Energy.
- **Payload Transmission**: When a user selects a card to emulate, the app serializes the card data (UID, Sectors, etc.) into a JSON payload and transmits it over a custom BLE characteristic.
- **Native UI Presentation**: Utilizes `NFCEmulationPresenter` to spawn a standard `NFCTagReaderSession`. While it doesn't strictly emulate the card using the iPhone's NFC chip (restricted by Apple), it provides the familiar native Apple Pay-style UI drop-down while the external hardware bridge does the actual emulation.

### Live Activities (Dynamic Island)
- **ActivityKit Integration**: When emulation begins, a Live Activity is started.
- **Dynamic Island UI**: Shows a compact leading icon and trailing countdown timer in the Dynamic Island.
- **Expanded UI**: When long-pressed, it expands to show the emulated card's name, remaining time, and bridge status.

## 2. Functionality Flows

### A. The Import Flow
1. **User Action**: Taps "+" in `CardLibraryView` to open `CardImportView`.
2. **Data Selection**: User selects a `.bin`/`.json` file or pastes from the clipboard.
3. **Parsing**: `CardImportManager` processes the data. If `.bin`, it reads the 1024 bytes (for MIFARE 1K), extracting the 4-byte UID from block 0, and slicing the data into 16 sectors.
4. **Validation**: The data is validated. If successful, a new `Card` SwiftData model is instantiated.
5. **Save**: `modelContext.save()` is called, and the card appears in the library.

### B. The Emulation Flow
1. **User Action**: Taps a card in `CardLibraryView`, opening `CardDetailView`.
2. **Trigger**: User taps "Emulate".
3. **Native UI & Activity**: `NFCEmulationPresenter` is invoked to show the native system NFC sheet ("Hold Near Reader"). Simultaneously, a Live Activity starts.
4. **BLE Transmission**: `BLEManager` constructs a JSON payload containing the command `"emulate"`, the `uid`, and the `sectors` data.
5. **Hardware Execution**: The payload is sent to the ESP32. The ESP32 parses the JSON and instructs the PN532 module to enter `TgInitAsTarget` mode, broadcasting the target UID and responding to reader authentication requests.
6. **Termination**: After the 30-second timer expires, or the user dismisses the native UI, a `"stop"` command is sent over BLE, and the Live Activity is terminated.

### C. The Hardware Settings Flow
1. **User Action**: Taps the gear icon in `CardLibraryView` to open `HardwareSettingsView`.
2. **Status Check**: The view binds to `BLEManager` to observe `isConnected`.
3. **Telemetry**: If connected, it displays the battery level and the last event received from the hardware bridge.
4. **OTA Mode**: The user can tap "Enter Firmware OTA Mode", which sends an `"ota"` command over BLE, rebooting the ESP32 into a Wi-Fi firmware update mode.

## 3. Key Components & Conditions

### `Card.swift` (SwiftData Model)
- **Condition**: Must contain `name`, `type`, `uid`, `atqa`, `sak`, and `sectors`.
- **Capability**: Stores custom images (`imageData`) and sorting index (`orderIndex`).

### `BLEManager.swift`
- **Condition**: Requires `NSBluetoothAlwaysUsageDescription` entitlement in `Info.plist`.
- **Capability**: Background scanning and auto-reconnection to the predefined Service UUID (`a0000000-0000-0000-0000-000000000001`).
- **Telemetry**: Reads from a `statusChar` to update battery and reader events in real-time.

### `NFCEmulationPresenter.swift`
- **Condition**: Requires `NFCReaderUsageDescription` in `Info.plist`.
- **Limitation Handling**: Checks `NFCTagReaderSession.readingAvailable`. On the iOS Simulator, it gracefully prints a warning instead of crashing. On physical devices, it handles the native UI presentation state.

### `keycardWidget`
- **Condition**: Requires `NSSupportsLiveActivities` set to `YES` in `Info.plist`.
- **Capability**: Binds to `EmulationAttributes` to track the state (time remaining, card name) and updates the Dynamic Island natively without opening the app.

## 4. Security & Limitations
- **No Direct iOS Emulation**: Due to Apple's strict sandboxing of the Secure Element and CoreNFC framework, true Host Card Emulation (HCE) of MIFARE Classic is impossible natively.
- **The Hardware Bridge Solution**: The app fundamentally relies on the ESP32/PN532 proxy bridge. The app acts as the secure vault and control interface, while the hardware performs the low-level RF negotiation.
- **Card Security**: Cards imported into SwiftData are currently stored in plain text within the App Sandbox. For production, enabling App Data Protection (Data Protection Entitlement) is highly recommended.
